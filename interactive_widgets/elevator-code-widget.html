Elevator Code Syndrome Extraction

One reusable logical ancilla rides a column of logical data qubits, collecting each outer-code (Hamming) bit-flip check by transversal CNOT.

Instructions
  1. Reset the logical ancilla.
  2. Collect the syndrome of a logical qubit with the transversal CNOT.
  3. Move the ancilla down the column (SWAP).
  4. Keep collecting & moving until the check is complete.
  5. Measure the ancilla.
  6. Repeat for all three outer-code checks, then decode.

Keyboard: Tab moves between controls, the register, and the footer. Enter or Space activates the focused button or highlighted block. Left / Right arrows move focus along a row of control buttons. Up / Down arrows swap the ancilla one floor when the register has focus. ESC resets the whole widget (the injected error is kept).

Before you start — the two codes, what each block is, and why the ancilla swaps

This is a concatenation of two classical codes. The outer [7,4,3] Hamming code, spread across the 7 logical data qubits, catches a single bit-flip (X) error — those are the three parity checks in this widget. If the classical code itself is new, the Hamming [7,4,3] Visualizer walks through it on plain bits first.

The inner [5,1,5] repetition code, inside every block, separately protects against phase-flip (Z) errors. The two codes guard against the two different error types independently.

You can exercise both. Set Error type in the controls to Z and run the three checks: the outer syndrome stays (0 0 0) — a phase flip commutes through the CNOTs and is invisible to bit-parity checks. Then run the inner phase-flip check to locate it. Each code is blind to exactly the error the other one catches.

Every block is a whole logical qubit. Each row in the register — the ancilla and all seven data qubits — is itself a [5,1,5] repetition code of 5 physical qubits, protecting against phase-flip (Z) errors. The little squares standing in for a row are those physical qubits.

The CNOT between two rows is transversal. It isn't one gate — it's 5 physical CNOTs firing in parallel, physical qubit i of the data block controlling physical qubit i of the ancilla. That copies the data block's bit value onto the ancilla so the outer Hamming check can read it.

Why swap at all? The hardware here is laid out as a line, and a transversal CNOT can only reach a block that is physically adjacent to the ancilla. It can't reach across the stack to a distant data qubit.

So the ancilla travels. A SWAP exchanges the ancilla with its neighbour — itself transversal (5 physical swaps) — stepping it one floor at a time until it lands beside the next qubit in the check. Swapping does not disturb the parity already collected; it only moves the car. That's the whole picture: SWAP is the ride between floors; CNOT is what it does when the doors open. (In a real compilation each SWAP is decomposed into 3 CNOTs; kept as a single SWAP here for clarity.)

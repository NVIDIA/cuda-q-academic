Exploring Logical Layers with CUDA-Q

Place interacting qubits together, choose their error-correcting codes, and compare physical resources and scheduled time across the logical compilation layers in CUDA-Q.

Start here for a simpler introduction to the logical compilation layers. Then explore Logical Rotation Synthesis for a deeper look at rotation synthesis, T-state factories, and resource budgets.

Instructions

The logical compilation layers in CUDA-Q are P0 (logical circuit), P1 (logical placement), P2 (error-correcting encoding), P3 (physical connectivity and schedule), and P4 (control signals). This widget follows that notation and stops at P3.

New to these circuits? See the Bernstein–Vazirani notebook and the Deutsch’s algorithm notebook.

  1. P0 · Circuit: choose a logical circuit, read its diagram, and answer the two counting questions.
  2. P1 · Regions: drag each logical qubit into a compute region (or select a qubit, then “Place in Region A/B”). Keep qubits joined by a CX gate together, then click “Check placement.”
  3. P2 · Encoding: pick a quantum error-correcting code for each region and watch the physical-qubit total update.
  4. P3 · Connectivity: try the SWAP exercise, then choose Grid or All-to-all connections for each region and compare gate counts and scheduled duration.
  5. After a valid placement in P1, use “View your CUDA-Q code” to copy or download a runnable script for your configuration.

All 176 configurations were precompiled using the logical capabilities in CUDA-Q. Results are model estimates, not hardware measurements.

P0 Choose the logical circuit

⌄

A logical qubit is one qubit in the algorithm. Its physical encoding is chosen later.

Gate key

H is a Hadamard gate (superposition and interference). S is a phase gate; two S gates make Z. CX is a controlled-NOT: the filled dot is the control, ⊕ is the target it flips. The meter symbol is measurement in the Z basis. The oracle implements f(x); q2 is its helper, and only q0 and q1 are measured. A red CX means its two qubits are in different regions.

P2 Choose each region’s encoding

⌄

A quantum error-correcting (QEC) code represents one logical qubit using a block of physical qubits. Data qubits carry the information; check helpers are reserved for error checks. These examples reserve helpers but do not run repeated error-check rounds.

P3 Connect and schedule physical qubits

⌄

The encoded gate implementations determine which physical qubits must interact. The device topology—its direct connections—can require extra SWAP gates to perform those interactions.

Why does connectivity matter?

Details on these numbers
  • Qubits in use: the full physical pool of every region that holds at least one logical qubit, including that region’s unused block capacity and routing reserve. Empty regions are not counted. This is an allocation, not a proven minimum.
  • Computed using the logical capabilities in CUDA-Q: code expansion, routing, and scheduling produce the captured results for each selection. Gate count: emitted native gates (the device’s primitive gate operations) after routing; includes SWAPs. Preparation and measurement are separate operations, excluded from the gate count but included in the schedule.
  • Timing inputs: a schedule assigns operation start times and allows independent work to overlap. We assume 1 µs per native gate, including SWAP; 3 µs per product readout/rotation. A SWAP is one native gate in this model, not three CX gates.
  • Regional composition: the preview compiler does not accept mixed encodings in one root program. We compile the disconnected workloads separately, sum gate counts, and take the longer scheduled duration. This assumes independent resources and simultaneous starts.
  • Scope: ideal encoded preparation and native multi-qubit product readout are abstract primitives. The graph constrains two-qubit gates, not the internal work of those primitives. There is no noise, decoding, or repeated correction. The supplied gate sequences are retained without global circuit simplification.
  • Not a default processor: grid connectivity uses the built-in topology constructor in CUDA-Q; a fixed grouped mapping with spare routing corridors and operation durations are explicit teaching inputs. All-to-all uses the public topology constructor with every pair connected. Switching connections keeps the pool and mapping fixed, including spare sites; changing a code rebuilds the pool. The reference surface target does not select a grid automatically.
